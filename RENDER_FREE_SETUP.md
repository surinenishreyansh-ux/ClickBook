# Render Free pilot deployment — ClickBook

The Render Free instance is only for a controlled pre-launch pilot. It has
**512 MiB RAM**, a single app process, ephemeral disk, and sleeps when idle.
It is **not suitable for a time-critical paid event** until load/AI latency,
resilience, monitoring and privacy have been validated.

## 1. Provision the service (no client data yet)

Create a Docker web service for the private ClickBook repository, `main` branch,
plan **Free**, Dockerfile `./Dockerfile`, root/context `.`.

Use these *safe initial values* (the provisioning tool generates a random
SECRET_KEY and stores it inside Render, not in Git):

```env
ENVIRONMENT=production
STORAGE_DRIVER=local
CLICKBOOK_SETUP_MODE=1
WEB_CONCURRENCY=1
```

`CLICKBOOK_SETUP_MODE=1` blocks all public routes except `/api/health` with
HTTP 503. This prevents users from sending real event photos to an ephemeral
local database/storage during setup. The health response includes
`"setup_required":true`.

## 2. Securely configure Neon + Cloudinary

From the **Render Dashboard** > ClickBook web service > **Environment**,
enter these values directly in the private environment UI:

```env
DATABASE_URL=postgresql+psycopg://<NEON_USER>:<NEON_PASSWORD>@<NEON_HOST>/neondb?sslmode=require
STORAGE_DRIVER=cloudinary
CLOUDINARY_CLOUD_NAME=<CLOUD_NAME>
CLOUDINARY_API_KEY=<API_KEY>
CLOUDINARY_API_SECRET=<API_SECRET>
CLOUDINARY_MAX_ASSET_MB=10
FRONTEND_URL=https://<ACTUAL_RENDER_HOSTNAME>.onrender.com
CLICKBOOK_ORIGINS=https://<ACTUAL_RENDER_HOSTNAME>.onrender.com
```

Do not paste credentials into ChatGPT or GitHub. The server also requires a
secure `SECRET_KEY`, already generated by the deployment setup.

If a database password was previously committed, rotate it in Neon first.

## 3. Migrations / first cloud test

Before switching setup mode off, confirm database connectivity and that
`/api/health` returns `database_connected: true` and
`storage_driver: cloudinary`. Since health reports database connectivity but
does not itself verify Cloudinary credentials, use a non-sensitive test upload
after enabling the app.

Set `CLICKBOOK_SETUP_MODE=0` in Render's Environment settings and allow the
service to redeploy. The React frontend is served by the same Docker image, so
a separate Cloudflare Pages deployment is not needed for this pilot.

To exercise the product:
1. Register an organizer account, create an event, and copy the guest QR link.
2. Invite a separate photographer account and accept the invitation.
3. Upload a harmless test JPEG from the photographer's phone.
4. Confirm the image appears in Cloudinary with **authenticated** delivery type,
   the guest gallery displays the photo, and unauthorized uploads fail.
5. Enable face discovery only after reviewing consent, running face-model tests,
   and confirming the 512 MiB instance does not crash or exceed memory limits.

## Important limits

- The Render Free instance may cold start after inactivity; a sleeping instance
  cannot guarantee instant gallery updates during a wedding or major event.
- Local image storage and SQLite are ephemeral. Never disable
  `CLICKBOOK_SETUP_MODE` until both Neon and Cloudinary are properly configured.
- Private Cloudinary photos are proxied through FastAPI and consume backend
  resources. Confirm limits before bringing paying clients.
- Setting `CLOUDINARY_API_SECRET` in Render enables live storage access; do not
  place it in `VITE_*` frontend variables.
- Production migrations/rollbacks, backups, abuse prevention, and load testing
  remain mandatory before accepting live paid events.
